# 客户需求调研材料

## 1. 文档定位

本材料用于模拟AI解决方案项目前期的客户需求调研。项目没有接触真实企业客户，因此下列内容是基于电竞外设B2B出口流程设计的访谈框架和POC假设，不宣称来自真实商业访谈。

## 2. 模拟客户背景

- 客户类型：中小型电竞外设出口企业
- 主要产品：鼠标、机械键盘、电竞耳机、客制化线材和键帽
- 主要客户：海外品牌商、分销商、零售商和电商卖家
- 当前系统：产品表格、共享邮箱和简单CRM
- 项目使用者：外贸业务员，销售主管为辅助使用者
- 项目边界：从收到英文询盘到形成首轮跟进决策

## 3. 现状流程（AS-IS）

```text
收到英文询盘
    ↓
人工阅读并提取产品参数
    ↓
在Excel或产品资料中查找SKU
    ↓
凭经验判断MOQ、定制可行性和询盘优先级
    ↓
向工程或主管确认不确定信息
    ↓
编写首轮英文回复
    ↓
手工记录到CRM
```

## 4. 关键痛点假设

| 痛点 | 业务影响 | AI机会 |
|---|---|---|
| 询盘格式不统一、参数分散 | 阅读和整理耗时 | LLM提取结构化需求 |
| 新业务员不熟悉全部SKU | 产品推荐依赖资深员工 | 查询结构化产品库并解释匹配证据 |
| 关键参数冲突容易遗漏 | 可能错误承诺标准产品 | 用硬约束规则拦截冲突 |
| 低质量和风险询盘混在一起 | 跟进资源分配不合理 | 分开质量提醒、商业提醒和真实风险 |
| 回复质量不稳定 | 客户体验和询盘转化受影响 | 按跟进策略生成英文草稿 |
| 过程没有统一记录 | 主管难以复盘 | 保存分析结果和下一步动作 |

## 5. 模拟访谈问题清单

### 业务流程

1. 每天大约收到多少封英文询盘？
2. 从阅读询盘到完成首轮回复平均需要多久？
3. 哪些产品参数最容易遗漏或理解错误？
4. 什么情况下业务员必须咨询工程师或销售主管？
5. 当前产品资料和历史客户信息存放在哪里？

### 询盘资格评估

1. 哪些信息决定一条询盘是否值得优先跟进？
2. MOQ、年度需求和客户类型如何影响优先级？
3. 如何区分信息不足、商业条件不明确和真实风险？
4. 哪些风险必须停止报价并转人工核查？

### 产品匹配

1. 五类产品各自有哪些不能妥协的关键参数？
2. 哪些需求属于轻度定制，哪些必须进入ODM评估？
3. 推荐产品时需要展示哪些理由和差距？
4. 客户所在国、销售市场和交付地点如何影响认证与产品选择？

### POC验收

1. 哪些字段提取正确才能认为分析可用？
2. 关键参数冲突是否必须100%拦截？
3. 回复草稿中禁止出现哪些商业承诺？
4. 业务员如何确认、修改和保存结果？

## 6. 结构化需求

### 功能需求

1. 支持粘贴英文询盘及上传TXT、DOCX。
2. 提取客户、采购、产品、定制和商业信息。
3. 分开客户所在国、目标市场和交付地点。
4. 查询五类产品的结构化产品库。
5. 将关键参数作为硬约束，冲突时不得判定为标准SKU。
6. 输出信息质量提醒、商业提醒和风险信号。
7. 生成线索得分、优先级、跟进策略和英文草稿。
8. 由业务员审核后保存CRM记录。
9. 通过FastAPI提供分析、产品查询和CRM接口。

### 非功能需求

- 输出必须可解释，展示匹配理由、差距和评分依据。
- 无模型API时，Demo模式仍可完成演示。
- 模型失败或JSON非法时回退到规则解析。
- 系统不得自动发送邮件或承诺价格、交期和认证。
- POC使用模拟产品和客户数据，不处理真实客户隐私数据。

## 7. 需求优先级

| 优先级 | 内容 |
|---|---|
| Must | 结构化提取、硬约束匹配、风险分层、评分路由、回复草稿、人工审核 |
| Should | FastAPI、CRM保存、Top 3候选、缺失问题生成 |
| Could | 真实CRM、邮件草稿接口、产品文档RAG |
| Won't in POC | 自动报价、自动发信、真实征信、制裁与贸易合规判断 |

## 8. 调研结论

该场景适合采用“LLM + 结构化数据库 + 简单规则 + 人工审核”的混合方案。LLM解决英文表达变化，数据库保证SKU事实，规则处理关键业务边界，业务员保留最终决策权。POC首先验证业务链路是否可行，不追求替代完整CRM或外贸管理系统。
