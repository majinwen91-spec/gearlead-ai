# POC测试报告

## 1. POC目标

验证GearLead AI能否在限定的电竞外设询盘场景中完成以下闭环：

```text
英文询盘 → 结构化提取 → 产品匹配 → 线索评分 → 跟进策略 → 回复草稿 → CRM记录
```

本报告只说明课程项目和合成数据上的验证结果，不代表生产环境准确率。

## 2. 测试范围

- 25条合成英文询盘
- 20个模拟产品SKU
- 五类产品：鼠标、键盘、耳机、线材、键帽
- 完整询盘、缺失询盘、ODM、低质量和风险场景
- Demo模式下的确定性工作流
- FastAPI五个基础接口

## 3. 验收标准

| 能力 | 验收标准 |
|---|---|
| 结构化提取 | 品类、数量和客户国家基础字段准确率不低于80% |
| 产品匹配 | 推荐SKU准确率不低于80% |
| 优先级 | High、Medium、Low、Risk Review准确率不低于75% |
| 缺失检查 | 已标注缺失字段召回率不低于80% |
| 工作流 | 七个业务步骤成功率不低于95% |
| 回复草稿 | 包含正文、署名和人工审核提示 |
| FastAPI | 五个接口可访问，非法短文本返回校验错误 |

## 4. 当前结果

| 指标 | 当前结果 |
|---|---:|
| 基础字段提取准确率 | 98.7% |
| 产品匹配准确率 | 100.0% |
| 优先级分类准确率 | 100.0% |
| 缺失字段召回率 | 97.4% |
| 工作流步骤成功率 | 100.0% |
| 回复格式完整率 | 100.0% |

这些结果来自参与过规则调优的小型合成回归集，只能证明当前受控案例能够稳定重复运行。

## 5. 关键业务反例

除原有25条案例外，自动化测试增加了以下关键反例：

1. 德国客户向美国市场销售并交付洛杉矶，三个地理字段必须分开。
2. 只问最低价的短询盘应标记为质量问题，而不是欺诈风险。
3. 要求向个人账户付款的询盘必须进入人工风险复核。
4. 全尺寸键盘要求热插拔但目录产品不支持时，不得判定为标准SKU。
5. `not hot-swappable`必须保存为明确的`false`要求，而不是误判为支持热插拔。

## 6. FastAPI验证

接口测试覆盖：

- `/health`返回服务状态。
- `/api/v1/inquiries/analyze`返回完整工作流结果。
- `/api/v1/products`按品类返回产品。
- `/api/v1/leads`可以保存并查询线索。
- 少于八个字符的询盘由Pydantic返回`422 Unprocessable Entity`。

## 7. 已知限制

- 询盘和标准答案均为合成数据。
- 基础字段准确率只统计品类、数量和客户国家。
- 产品库没有真实库存、报价、认证文件和版本信息。
- 规则解析器不能覆盖所有真实英文表达。
- LLM路径依赖外部模型服务，当前回归测试使用Demo模式。
- 回复格式完整不等于回复内容一定适合真实客户。
- 系统没有自动发送邮件，所有结果必须由业务员审核。

## 8. POC结论

POC已经证明业务流程可以被拆成稳定的结构化步骤，并能够通过Streamlit演示和FastAPI接口运行。系统适合作为AI解决方案课程项目和面试作品集，但不能宣称已经达到真实企业生产可用水平。

下一阶段若进入真实试点，应优先验证匿名真实询盘、资深业务员标注、模型输出纠错率和业务员采纳率，而不是继续增加前端或基础设施复杂度。
